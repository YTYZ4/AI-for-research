# 完整单边、混合任务拒绝与两项评分修复

当前v0.11.10，230项本地测试通过。45次定向真实API回归原始37/45、格式后37/45、本地后43/45。完整单边正向、反向、零容量9/9通过；混合任务仍有1次变相删目标建议被自动检查漏过，不能宣布全部解决。旧失败与统计均保留。

## 实现与评分修复

完整单边问题的共因是将“只有一条边”误认为信息不足。新增窄范围原文完整性证据，仅识别明确有向、两个节点、一条带原始数值/单位的边、声明无其他边的输入。发现未知/条件性/矛盾边记录时不提供该证据。证据逐字引用原题，随请求保存；不决定数学合法性，不改模型状态，不合成拒绝说明。没有证据不代表题目不完整。

混合任务契约明确只解释联合要求及单模型边界，不建议拆分、分别提交、一次只提交一项，也不附加无关数值限制。

两项评分修复：
- “若仅求最大流，可处理……”可作为条件性支持边界介绍，不再自动等同改题建议；真正的“请删除费用”“建议改为”等仍拒绝。
- “不能联合表示并求解”纳入能力限制等价表达；“可以联合表示”和仅重复任务名称仍不通过。
- 额外增加拆分/分别提交建议检查及否定对照。

graph_units、graph_quotes、model、capacity_conflict、parameter_policy、dimension_policy、missing_capacity、source_quotes、format_repair九个护栏模块与v0.11.9快照逐字相同。没有通过关闭数值、单位或引用验证提高通过率。

## 本地和离线验证

230项测试通过，新增8个测试方法，覆盖完整单边原文跨度、缺容量/方向、非闭合边集、重复边记录、节点不匹配、条件性语句；完整性证据不等于参数域合法；错误追问在有证据时仍原样保留，不自动翻转。

旧两条评分误判按新规则离线通过；旧拆分建议按新规则失败。旧完整单边多余追问经新生成流程离线重放仍原样保留。零API单列，不修改历史评分。

## 保留失败与评分漏检

两个自动失败均为flow_missing_direction：
- 第2次needs_clarification、model=null，文本为“缺少边S—T的方向：最大流需要每条边的方向”，告知了缺项，但没有明确确认/提供请求，未满足冻结的追问条件。保守评分边界单列，不擅自改成通过。
- 第3次追问内容正确，但漏掉必填model:null，结构验证失败。没有用受限格式修复补字段，没有执行模型。

逐条复核9条混合响应发现：mixed_production第2次虽正确unsupported且未求解子任务，仍写“请将实际需要解决的任务限定为其中一种”。这与本轮不要求删目标的意图不符，现有词法检查漏掉该同义表达。自动9/9保留，但不能解读为解释全部合格。其余8条未见拆分/删目标建议。后续应针对该同义表达补评分及生成约束，而不能把本轮统计隐藏或覆盖。

评分修复与生成修改同时发生，不能把新旧通过率差异全归因于模型改进。本轮是开发题定向观察，未进行完整开发回归或保留题泛化实验。语义复核由开发助手完成，非独立人工评分。
