# 容量冲突优先澄清与重复评测

2026-10-16，v0.10.8，deepseek-flash。117项本地测试通过。

## 统一策略

先核对容量原文是否冲突，再校验单一参数的合法范围。同一常参数Logistic题面出现不同容量记录时，列出原值、说明冲突、询问哪条准确或是否有不同适用条件；不选较大值、正值或最后出现的值，不创建求解模型。即使其中有K=0且用户禁止改参数，也不能越过记录核对直接停止。核对记录与建议修改数值分开。

若模型已正确指出全部值并追问，保留原响应，不算本地接管；否则本地输出固定澄清，local_validation保存原响应、全部原文引用及未执行标志。相同数值（含0.5与0.50）不算冲突；明确更正、不同单位、多个种群、干预或时变条件不由此狭窄规则自动判断，交给模型处理。

本地测试覆盖冲突优先于无效值停止、错误ready不被执行、正确追问不计接管、重复值、显式更正、多种群和单位差异。原“禁止改值且单一原值无效”策略保留。

## 剩余问题

- round_1/missing在正确询问容量后，额外要求增长率与容量单位一致。这不合理：增长率是反时间，容量是数量。自动评分只查状态与主题，未捕获该文字错误；原计数保持不变，另记警告。
- 部分冲突追问在核对原记录后追加“提供正实数K”。本轮没有自行选值或执行，但这种措辞可能引导选择有效值；更严谨的交互应先核实原记录，再校验其合法性。
- 本地冲突识别是受限规则，不保证所有不同对象、跨句省略或单位表达都能正确理解。每场景3次不证明长期稳定，未重跑统一47场景或保留测试。

因此，本轮目标行为（指出容量冲突并先追问、不自行选值或直接停止）均通过，但不能把30/30解释成所有语义说明完全正确。
