# 容量数值等价写法与重复评测

2026-10-16，版本0.10.10，deepseek-flash。126项本地测试通过。

## 修改

容量记录使用Decimal精确比较，支持小数末尾零、省略前导零、正负号、整数/小数与科学计数法。0.5、0.50、.5、+0.5、5e-1相等；0.5与0.5001不相等。比较不使用容差，也不使用二进制浮点先舍入再判等，单元测试覆盖极近但不同的十进制数。

请求前将原始写法、原文引用、exact_values以及equivalent/conflicting结果作为本地核对提示交给模型，并在capacity_record_check保留。正常预处理不计本地纠错通过；不强行把needs_clarification转成ready。原值不改写、原始响应不覆盖，求解字段按既有数值流程处理。

统一数字解析支持科学计数法与省略前导零的source_quotes校验。等价不代表合法或完整：负零等于零但K=0仍无效；缺增长率仍应追问。不同数量单位、多种群、明确更正不由此局部规则强判。旧失败原题离线正确识别为equivalent，[原输入核对](../../outputs/equivalent_regressions/20261016_212625_f5fb4334/historical_input_check.json)，不算原响应已修复或额外在线通过。

## 剩余问题与计数解释

1. leading_dot第1次：原文中逗号被模型在source_quotes拼成分号，引用不是逐字原文。提取K=0.5正确，但来源校验按既定规则拒绝执行。这是引用生成失败，不是数值等价比较失败。
2. same_invalid第3次：模型正确unsupported后又建议提供正数K或允许调整，违反原题禁止改参数。已有本地策略对unsupported直接放行，未处理这个建议。错误原文保留，未重试覆盖。
3. near_difference第2次计为本地新增通过：原回答已列出0.5和0.5001并请求核对，但缺少严格要求的“冲突/矛盾/不一致”字样，因此被固定模板替换。它不是数学判断修复；原始27/30是当前严格规则口径，不能把该1例宣传为挽救了错误数学答案。

目标数值等价误判在本轮未复现，但整体仍有引用与拒绝措辞问题。下一步应将真实引用提取与模型生成引用进一步分离，并检查unsupported里的改值建议；也应改进语义评分，区分合理重述与实质错误。当前仅开发重复评测，未重跑统一47场景，不证明长期稳定或保留题泛化。
