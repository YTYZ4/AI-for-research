## 失败分析与边界

本轮没有数值或结构自动评分失败。逐份由Codex复核文字说明，发现FIT01一处说明警告：模型assumptions写“不会输出拟合系数”，但本地程序实际保存并展示系数。它不改变系数或误差，但会误导读者，应在后续说明生成中修正；本轮原响应和评分不回写覆盖。其余七题本次未发现实质性语义变化。该复核不是独立人工双评或完整14分量表，不能称人工评测全通过。

失败分类与证据机制已通过模拟测试：生成/网络/响应错误、意外追问、不支持、求解错误、运行时验证失败、原题评分失败、评分器自身异常分别记录。单题失败继续后续题；评分器异常不能计作模型错误。已收取响应但格式错误时保留API响应和usage；无usage时标未知，不记为零。

61项自动测试通过（其中原有模拟HTTP测试改为符合真实HTTP的字节流）；新增验证包括删掉原题约束但保留正确答案仍须评分失败、澄清不能算通过、失败后继续、评分器异常单列、非法JSON审计记录不含密钥。另有一轮人工参考模型离线8/8演练，仅验证管线，不计作LLM实验。线上运行快照保留当时实现，之后仅补强非对象响应审计和测试覆盖，未改动这轮结果或重新调用。

## 使用

```bash
# 真实模型：八次调用，每次最多6000输出tokens，不自动重试
.venv/bin/python -m evaluation.batch --backend deepseek

# 人工参考模型离线演练，不调用API
.venv/bin/python -m evaluation.batch --backend reference
```

每次创建独立批次目录。results.csv/results.json保存逐题结果、耗时、token、失败分类和运行路径；summary.md用于阅读。各题api.json保存请求和响应，generation_record.json先于求解保存，evaluation.json记录独立评分，case_result.json包含失败详情。HTTP错误未取得有效响应时可能没有api.json。

## 结论范围与下一步

这是固定八题、单模型、单次的开发基线；8/8不是新题泛化率或稳定成功率。三组主对照、重复运行、修复对照、保留题和外部试用尚未开展。优化结构评分较严格，数学等价的重写可能需要人工复核。自动评分不完整覆盖自然语言说明、所有单位换算或拟合协议的恶意篡改。模型别名与默认采样可能随服务更新变化；已记录请求和返回模型名，不能保证重新调用逐字复现。

下一步先固定语义评分与失败分类口径，增加开发题的同义改写、缺信息和错误条件版本，再做重复批次，最后冻结保留题与三组对照协议。不要用本轮8/8替代这些工作。
