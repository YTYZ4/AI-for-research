# 非法参数澄清修复与数据/单位定向回归

2026-10-16，版本0.7.0。沿用上一轮失败记录，不覆盖64次开发变体评测。本轮新增结构化本地反馈、数据质量输入检查和单位换算定向评测。

## 修复内容

- 提示词明确Logistic环境容量K<=0、负速率和非正时长不能直接ready；不得替换数值。
- 即使模型仍生成非法动态参数，本地以ModelClarificationError转成needs_clarification，保留原始响应、usage以及local_validation标志。无效模型不执行，不擅自补值。此为本地护栏，不能算模型原始回答正确。
- 交互模式允许用户明确给出修正值后再次调用。模拟测试覆盖K=0→询问→用户修正K=1000→正常积分；该模拟不计真实API验收。
- 报告标注追问是否来自本地参数校验。
- CSV错误包含行号和纠正指引；缺值、NaN、非法split、无留出集、错误表头在请求模型前拒绝。训练x全部相同也在本地预检拒绝，避免付费后才发现不可辨识。没有自动填值、删行或重新划分。

## 新发现：单位兼容不等于换算正确

Logistic单位题第一次返回time_unit=day、duration=30，却将rate从0.2/天改成0.008333333333333333/天。说明文字也重复了这个错误。正确方式可以是保持0.2/天、模拟30天，或者转换成0.008333333333333333/小时、模拟720小时。

该错误模型内部单位字段一致，模型自己的解析解也能对得上，现有运行时校验因而不能发现原题被改错。新增独立评分将模型时间和速率转换回原题天单位，对照固定原始增长率与解析轨迹；最大轨迹偏差约853.322个，明确判失败。第二次保留0.2/天并将720小时换为30天，正确。

这次是真正的一次失败一次成功，区别于上一轮评测器空值误报；不调整为通过、不重试刷成功。下一优先项是保留原始数值/单位并用确定性转换程序执行单位换算，且分别评价源参数抽取和换算，不能只继续加强“单位一致”提示。

## 验证与边界

71项程序测试通过：新增护栏保留原始错误模型与审计、交互修正后继续、坏CSV不调用模型、六类数据错误及正对照、单位评分器能拒绝“字段一致但数值换算错误”的模型。

本轮不代表完整四类能力的全面回归。缺失值插补、异常值处理、分组/时序划分、重复样本泄漏、更多单位和量纲检查尚未实现。训练x恒定被拒绝是当前只支持1–5阶多项式的能力边界，不代表不能拟合常数模型。新的图/动态规格仍不能保证原题数值提取一定正确。
