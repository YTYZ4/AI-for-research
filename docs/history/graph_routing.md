# 图结构与目标证据路由：共因修复及定向回归

助手v0.11.9；批次于2026-10-16晚启动，本报告于10月17日整理。原成本目标改写3/3正确返回unsupported并说明费用目标未支持，未再要求改成其他任务。222项本地测试通过。完整定向批42次三层34/42、34/42、39/42，仍保留3项自动失败，不宣称全部完成。

## 共因与修改

旧路由只匹配“最大流、最小费用流”等固定算法名称。原题虽明确有向网络、节点、容量及“先让流量最大，再让运输总成本最小”，却因缺少这些连写名称而走general路径，未使用图输入契约。简单添加“成本最低”又会误收生产、运输等优化任务，因此本次改为两类证据：
- 明确命名的图任务；或
- 图结构（网络、节点、管网等）与图目标（流量/输送量/吞吐量最大、费用/成本最低、路线最短等）共同出现。

graph_routing保存每个命中的原文片段和字符位置，随request_contract.routing_evidence写入API审计。路由只选择请求契约，不决定支持状态、不生成答案、不修改拒绝。负面或背景目标由模型阅读全文解释；不是看到费用就拒绝。

出现拟合、Logistic、生产计划等其他题型时仍保守回到完整Schema，避免把联合任务压成一张图；此时附带核对联合要求的规则，不允许只返回一个子任务。混合关键词可能只是背景，仍要求模型结合全文判断，不能声称已完成通用意图分类。

graph_units、graph_quotes、model、capacity_conflict、parameter_policy、dimension_policy、missing_capacity、source_quotes、format_repair九个护栏模块与v0.11.8快照逐字相同。

## 测试与旧失败重放

222项本地测试通过，新增5个测试方法，覆盖结构+目标同义表达、只有结构/只有成本目标的反例、混合任务保持完整Schema、否定费用目标不强制unsupported、原失败命中新契约，以及证据跨度逐字核对。

旧失败原响应经新流程离线重放仍保持needs_clarification，未被程序翻转或补写。只有请求路由由general变为graph_source_only。零API重放另列，不计下方42次。

## 三项自动失败与剩余问题

1. flow_reverse_conversion第1次：题目已声明只有S到T一条边、无其他边，模型仍索要完整网络或确认。这是实际多余追问，不是引用校验失败。没有执行求解。
2. flow_cost_priority第3次：模型正确拒绝费用目标，又用“若仅求……”说明支持边界。评分将其保守判为改题建议；没有直接要求换题或提交替代模型，但说明冗余，仍宜精简。
3. mixed_logistic第3次：正确说明“当前单模型协议不能联合表示并求解”，评分未覆盖“不能联合表示”措辞。这是词法评分误判，原结果保留。

另外，混合任务的多条拒绝仍建议“拆分/分别提交”，现有附加断言规则未覆盖这些措辞；另有一次无必要地附加整数容量条件。它们没有造成静默删除目标并求解，但说明质量尚未完全满足简洁、只解释原任务限制的要求。不能因为自动通过就称拒绝说明全部准确或无多余建议。

本轮核心目标场景未复现错误追问，支持“路由契约缺失得到修复”的开发观察；没有消融实验、独立保留题验证或完整开发回归，不能据此宣称普遍泛化。后续仍需处理完整单边网络的多余追问、混合任务拒绝中的拆分建议及评价词法覆盖。
